---\nname: coverage-coincidence-attribution\ndescription: Coverage-honest rescore methodology for attribution tasks. Addresses the trap where periodic events (OpEx, quarter-end, earnings) appear to explain FTD episodes purely because their calendar windows cover a large fraction of trading days.\n---\n\n# Coverage-Coincidence Attribution (V2r methodology)\n\n## The trap\n\nPeriodic calendar events (options expiry, quarter-ends, earnings) have windows that cover a significant fraction of all trading days. OpEx ±2td covers ~14% of trading days. When you match FTD episodes to the nearest OpEx date, you'll mechanically get ~14% of episodes matching — even if there's NO causal relationship between OpEx and the episode.\n\n**This is NOT a shuffle null test against random dates.** A simple temporal shuffle (±365 days, as in M1) doesn't correct for it either, because the calendar structure of the events is preserved. The correct null preserves the per-name episode structure but replaces episode dates with **uniform random trading days from the same year**.\n\n## Methodology (V2r protocol)\n\n### N1 — Coverage fractions\nFor each attribution class, compute:\n\n```\ncoverage_% = trading_days_inside_any_class_window / total_trading_days\n```\n\nWhere `trading_days_inside_window` counts how many of the total trading days fall within the class's window of ANY event in that class (union, not per-event).\n\nPer-class windows:\n- OpEx ±2td: 5 trading days window (3rd Fri ± 2 trading days)\n- Quarter-end ±3td: 7 trading days window\n- Others: ±5td default (11 trading days), ±10td for delistings\n\n### N2 — Honest null (1000 rounds)\n\nFor each round:\n1. For each (ticker, year) pair, preserve the exact count of episodes\n2. Replace each episode's date with a **uniform random trading day** from the same year\n3. Run the first-match-wins attribution pipeline on the null episodes\n4. Record per-class attribution rates\n\nCritical optimization: **pre-compute the lookup table** — for each ticker and each trading day, determine which class matches first (A → B → D → E → G → Earnings → Split → Registry → Unexplained). Then each null round is just `random.choice` from the pre-computed options per (ticker, year). This reduces 1000-round nulls from ~500s to ~10s.\n\n```python\n# Pre-compute: ticker -> {trading_day -> first_matching_class}\nlookup = {}  # ticker: {date: class_name}\nfor t in tickers:\n    ld = {}\n    for td in trading_days:\n        if td in a_covered: ld[td] = 'A_OPEX'\n        elif td in b_covered: ld[td] = 'B_QEND'\n        elif td in ticker_d[t]: ld[td] = 'D_DIVIDEND'\n        ...\n        else: ld[td] = 'UNEXPLAINED'\n    lookup[t] = ld\n\n# Null round: just random.choice from pre-computed\nfor (t, y), cnt in ticker_year_counts.items():\n    opts = ticker_year_options[(t, y)]  # list of (day, class)\n    for _ in range(cnt):\n        _, cl = random.choice(opts)\n        round_cc[cl] += 1\n```\n\n### N3 — Rescore table\n\nFor each class, compute:\n- `coverage_%` (N1)\n- `observed_%` (attribution rate on real data)\n- `null_mean`, `null_std`, `null_p5`, `null_p95` (from 1000-round null)\n- **Verdict**:\n  - `EXPLAINED` — observed_% > null_p95 (genuine trigger class)\n  - `ANTI_CLUSTERED` — observed_% < null_p5 (events systematically avoid this class — also a finding)\n  - `AT_CHANCE` — observed within null range (coverage coincidence)\n\n### N4 — True EXPLAINED recalculation\n\nOnly classes with `EXPLAINED` verdict count toward true explained:\n```\ntrue_explained = sum(obs_n for class in classes if verdict == 'EXPLAINED')\ntrue_unexplained = total_episodes - true_explained\n```\n\nThis typically collapses explained rates dramatically. In the FORCED_COVERING_DETECTOR project, raw V2 attribution showed 32.87% explained; V2r honest rescore showed 5.50% — a 27pp collapse.\n\n## Results from FORCED_COVERING_DETECTOR (ATTRIBUTION_V2r)\n\n| Class | Coverage% | Observed% | Nullμ% | Verdict |\n|:---|---:|---:|---:|:---|\n| A_OPEX | 14.15 | 9.77 | 9.56 | AT_CHANCE |\n| B_QEND | 7.62 | 4.97 | 5.18 | AT_CHANCE |\n| D_DIVIDEND | 100.00 | 5.47 | 4.94 | EXPLAINED |\n| EARNINGS | 99.24 | 1.67 | 1.56 | AT_CHANCE |\n| G_INDEX | 0.88 | 0.03 | 0.00 | EXPLAINED (trivial) |\n\nKey finding: **scheduled-date settlement calm** — OpEx and QEND show AT_CHANCE or ANTI_CLUSTERED patterns. The only genuine trigger is D_DIVIDEND.\n\n## EFTS limitations for attribution\n\n- EFTS has NO `ticker` field — tickers are embedded in `display_names[]` as prose. Extract with regex: `re.search(r'\\(' + re.escape(ticker) + r'[\\)\\,]', display_name)`\n- EFTS does NOT index EFFECT forms. The search `{ticker} AND EFFECT` returns 8-K forms that mention the word \"effect\", not actual EFFECT filings. Use SEC browse-edgar (`sec.gov/cgi-bin/browse-edgar?CIK={cik}&type=EFFECT`) instead, but this is CIK-required and slow.\n- When searching for 424B forms, combine ticker text search with form-type verification from the `form` field. Filter to `424B1`, `424B4`, `424B5` only — skip `424B3` (ATM/no-close per R3 rules).\n\n## Data walls encountered\n\n| Class | Wall reason |\n|:---|---|\n| C — ETF_FLOW | No ETF holdings cached (basket_etfs empty in crowding_map) |\n| F — TENDER | C7 calendar entries lack expiration dates |\n| H — DELIST | EODHD fundamentals returned 0 delistings |\n| I — EFFECT | EFTS doesn't index EFFECT forms; SEC browse-edgar too slow for bulk |\n\n## Trading days calendar construction\n\nFor coverage computation, use 2013-2025 (the longest stable period for FTD data). Exclude weekends and major U.S. holidays (New Year's, MLK, Presidents, Memorial, Juneteenth >=2021, July 4, Labor Day, Thanksgiving, Christmas).\n\n```python\ntdays = []\nfor y in range(2013, 2026):\n    d = date(y, 1, 1)\n    while d.year == y:\n        if d.weekday() < 5: tdays.append(d)\n        d += timedelta(days=1)\nholidays = set()\nfor y in range(2013, 2026):\n    holidays.update([date(y, 1, 1), date(y, 7, 4), date(y, 12, 25)])\n    # MLK: 3rd Monday Jan; Pres: 3rd Monday Feb; Mem: last Monday May; Labor: 1st Monday Sep; Thanks: 4th Thursday Nov\n    if y >= 2021: holidays.add(date(y, 6, 19))\ntdays_clean = sorted(set(tdays) - holidays)\n```
