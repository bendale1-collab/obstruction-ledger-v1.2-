N-first. That is a weakness of the measurement script's sentence linking, not

it should be known before code exists.

## Properties (properties.py; no check code referenced; MIN_EXAMPLES = 200)
- same_value_rendered_two_ways: prose is the table value rounded to k <= its
  significant digits under section 2. Must be SILENT.
- identical_strings: prose and table carry the identical numeral string and
  unit. Must be SILENT.

Each property was falsified against the sealed rule before commit (1000
examples, 0 violations after the constraints below). The first draft of
same_value_rendered_two_ways FAILED that test at 74/200 and exposed two
ambiguities in section 2, filed here pre-run and NOT resolved by the property:

1. Integer trailing zeros. "Fewer significant digits of the pair" does not say
   whether 100000 has one significant digit or six. Under a literal rendered-
   digit count, table 123456 vs prose 100000 fires. The property stays out of
   this region (no integer rendering ending in zero on either side).
2. Decade carry. Rounding 0.983938 to one digit gives 1, rendered "1.0" (two
   digits); the rule recounts, rounds the table to 0.98, and fires. The property
   stays out of this region (rounding must not change the decade).

Both are K2 spec items. The sealed rule is tested as sealed.

Known consequence, stated: under section 2 a prose "2" matches table 2.4 (one
significant digit). The property generates such cases; they are SILENT by the
sealed rule. If judged too lenient, that too is a K2 spec item.
